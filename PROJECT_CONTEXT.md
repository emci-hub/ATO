# PROJECT_CONTEXT.md

## What ATO is
A self-based alternative to Costar-style astrology apps. Instead of generic daily content, it uses a multi-axis personality/behavior framework to generate accurate, personalized guidance. Goal: help users understand themselves and how they interact with others (e.g. why an extrovert might overwhelm an introvert), and nudge them toward growth and new experiences.

**Confirmed 16 axes** (`TRAIT_AXES` in `src/lib/traits.ts:15`): openness, conscientiousness, extraversion, agreeableness, steadiness, attachment_anxiety, attachment_avoidance, conflict_assertiveness, conflict_cooperativeness, autonomy, competence, relatedness, growth_mindset, locus_of_control, self_efficacy, playfulness.

- 2026-09-03: **Fixed: unexpected sign-outs — Supabase auto-refresh now ticks on app foreground/background (`src/lib/supabase.ts`).** Emci reported the app kept signing them out. First hypothesis (`changeAuthPassword()`'s `signInWithPassword` re-verify tearing down the session on a wrong current password) was investigated, proposed, and then disproven by reading `node_modules/@supabase/auth-js` directly — that call returns on error without touching session state; reverted before commit, no net change to `auth-password.ts`. Real cause: RN throttles JS timers while backgrounded, so the client's internal refresh tick can miss its window; by the time the app foregrounds, the access token has often fully expired rather than just being near-expiry, and GoTrue's `_callRefreshToken` treats an expired-token refresh failure as "genuinely dead" and hard-signs-out (`_removeSession()`) instead of the soft-preserve path it takes for a still-valid token. Fix: an `AppState` listener calls `supabase.auth.startAutoRefresh()`/`stopAutoRefresh()` on active/background — the exact pattern documented in the `@supabase/auth-js` JSDoc itself, web excluded (web manages its own `visibilitychange` refresh internally; calling `startAutoRefresh()` there would tear that down). Reviewer passed with two non-blocking notes: this reduces the failure window rather than eliminating it entirely (a long-enough background stretch can still hit the same path), and the module-scope listener is fine for an app-lifetime singleton client (no cleanup needed) but will register twice under dev Fast Refresh (harmless — old client's ticker self-stops). Gate green: typecheck + lint + 49 checks. Not yet OTA'd — worth a real device background/foreground test before publishing.
