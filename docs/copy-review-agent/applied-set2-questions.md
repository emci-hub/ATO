## Retire mechanism (wave100, emci 2026-10-20, approved; NOT applied)

**What it does.** A question whose scene changes keeps its id and ORIGINAL text forever (answers point at the id and keep showing it); it gets `question_bank.retired_at` and is never served, never offered in Change answers, and its id is never reused. The new scene is a NEW id: the next free number in its trait (`<trait>_26`, `_27` …), same trait, setting, direction (`unflattering`), value scheme and high-option position, so the per-trait balance rules still hold. Wording-only edits stay in-place (wave99). Copies the `ai_library_cards.retired_at` idea (wave93: nullable, null = live, rows never deleted).

**Progress rule (server and phone, identical).** Answered on a trait = min(active rows on the trait, every row the person answered on it, retired ones included). Sets done = the lowest trait; bank complete = every trait at its active count. So retiring never moves anyone backward or forward: someone who finished all 25 sets stays finished, someone at set 10 still has 15 sets left, and someone who answered a retired question needs one fewer active question on that trait (its replacement may never be served to them). A trait is never served past 25 answers.

**Client.** `BankQuestion.retired = { wave, replacedBy }` (`src/lib/questions/bank/define.ts`, helper `retired(newId, q(...))`). `BANK_ROWS_BY_TRAIT` / `QUESTION_BANK_ALL` hold every row (lookups, counting answers); `BANK_BY_TRAIT` / `QUESTION_BANK` hold the 25 / 400 active rows (serving). `bankQuestionById` still resolves retired ids. `bankProgressFrom` and `pickBankSet` use the progress rule above (`answeredOnTrait`). The Change answers list (`bank-finish-fold.tsx`) still shows a retired question someone answered, with its original words and their answer, read-only, under "We retired this question. Your answer stays as you gave it."

**Server functions** (`supabase/migrations/wave100_question_retire.sql`; each is its current definition word for word plus only the retired filter, pinned by `check:question-bank` against its source text; grants identical):

| `serve_bank_set()` | wave85_fixed_question_bank.sql | sets done through the helper; both passes serve only active rows on traits not yet full; the fill pass never gives a trait more than it still needs |
| `dev_fill_bank()` | wave85_fixed_question_bank.sql | answers only active rows, only up to each trait's active count |

### Apply order and what ships together

1. **OTA first** (the client bank with retired rows and the _26+ ids, `bank-sets.ts`, `bank-finish-fold.tsx`). This client works against the CURRENT server too: with nothing retired server-side it counts exactly as before, and the old server never serves a _26+ id.
2. **Then `wave100_question_retire.sql`.** Before applying, compare the live bodies of `serve_bank_set`, `_bank_all_done`, `dev_fill_bank`, `change_bank_answer`, `serve_bank_retest` with their sources (pg_get_functiondef) in case one was edited by hand. Alone it changes nothing visible (no row retired yet).
3. **Right after, same session: `wave100b_question_retire_rows.sql`.** It needs the column and the new functions (without them the old `serve_bank_set` would serve 29 rows on attachment_avoidance and let a trait reach 26+).

Compatibility:
- **Old app bundle + new server: breaks for some people.** An old bundle counts progress only over the ids it knows (01-25). Once someone is served a _26+ question, that trait stalls below 25 on their phone: the set line shows the wrong set, and at the end the phone never reaches "All 25 sets done" while the server says `bank complete` (serving fails, Change answers and Start Fresh never appear). Their answers and scores are still correct on the server. So wait for OTA adoption before step 2-3.
- **New app bundle + old server: works.** Nothing is retired, every served id is known, progress counts are identical to today.
- **Open sets at apply time:** an item already served for a now-retired question stays in its open set and can be answered (scored from the retired row's own options, counted as answered). Nothing in an open set is rewritten.
- **Change answers:** a retired question someone answered stays visible with their answer, read-only; the server refuses to change it (`'retired question'`). Start Fresh clears answers as before, after which only active rows are served.
