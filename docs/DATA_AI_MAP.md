## Sample provenance legend

Every sample in the table is tagged. Nothing in this document is invented or paraphrased.

- **REAL** — text produced by the running app and read back out of the live database.
- **FIXTURE** — the row is in the live database, but the text was seeded, not generated by
  the app. Proven, not assumed: see the two notes below.
- **BANK** — static copy that lives in the repo, quoted verbatim, *and* with database
  evidence that this exact surface was served to an account. Deterministic, so the stored
  string and the rendered string are identical.
- **BANK (repo only)** — static copy quoted verbatim, but no database evidence it has ever
  rendered. Treated as "no real sample" for the purposes of the missing-sample list.
- **none** — "no sample available — untested/unused".

### Why the `checks` rows are FIXTURE, not REAL

The `riley` / `sam` rows are the only Read/Do/Nudge text in the database, and they are seeded:

1. `read_text: "One real thing, then stop."` appears verbatim as a hard-coded fixture in
   `scripts/home-hydrate-check.ts:56`. It is not in `src/app/copy/first_cards.md`.
2. `source` is `bank` on days 3–9, but `BANK` (parsed from `first_cards.md` by
   `parseBank` in `src/lib/voice/bank.ts:36`) only contains days 1–3, so
   `bankCardForMe` cannot return a card for day 4+.
3. The stored Nudge reads *"something that **is** still true"*, while the only template that
   can produce that sentence (`composeNudge`, `src/lib/voice/nudge.ts:119`) writes
   *"something that**'s** still true"*. `git log -S "that is still true"` on that file returns
   nothing, so no build ever emitted the stored wording.
4. `created_at` values are exactly `02:00:00+00`, and the account `created_at` is exactly
   `06:00:00+00`.

**Consequence: there is no real, app-generated Read or Do anywhere in this project's data.**

### Why the Explore and Questions rows are REAL

`explore_entries` and `question_items` are on account `test` (`57afe286`), created
22:23 and 23:02 UTC on Aug 29. The Explore prose does not match
`composeLocalExplore` (`src/lib/explore/local.ts`), whose output is short template
concatenation, so it came from the live model. The question batch is confirmed live by
`ai_usage.by_type.questions = 1`, which is only written by `claim_questions_batch` on a
live regeneration.

## Guardrails checked (from `src/app/voice/sage.txt` + plan spec)

- **G1 Maybe, not fact** — patterns reflected as hypotheses. No "you are X".
  (`sage.txt`: "Never a verdict. Never 'you are X'"; hedge inside the sentence, never bolted on.)
- **G2 No framework names** — no MBTI / OCEAN / attachment / locus / mindset / SDT labels
  surfaced. Enforced by `containsFrameworkTerm` (`src/lib/voice/framework-fence.ts`),
  word-level `matchingJargonTerm` (`jargon.ts`), phrase-level `matchingPhrasePattern`
  (`phrase-guard.ts`).
- **G3 One trait at a time** — one axis per surface. Explore may combine 2–3 only on a
  recent signal, never the three agency axes together.
- **G4 Notice, don't correct** — observation, not instruction or fix.
- **G5 Crisis copy never model-generated** — static only (`src/lib/crisis/copy.ts`).
- **G6 Damping on inferred writes** — `0.12 * signal + 0.88 * old` (null old = 0.5),
  `blendInferredTrait` (`src/lib/traits.ts:185`). Direct sources full-replace and are sticky.

## Flags

**F1 — Gut Call writes are not damped (live, post-fix).** `me.autonomy` on account `test`
is `0.8` with source `self_game`, touched `2026-08-29T22:22:01.410Z`. `SCENARIO_HIGH` is
`0.8` (`src/lib/scenario.ts:26`) and `applyScenarioWrite` routes through `mergeTraitWrite`,
so with a null prior the stored value should be `0.12 × 0.8 + 0.88 × 0.5 = 0.54`. The write
happened after the damping commit `4e2259e` (Aug 29, 13:15 −0600). This corroborates the
"Gut Call regression — still open" line in `docs/NOW.md`. The four `self_situation` axes on
the same account are also raw, but those writes are 29 minutes *before* the damping commit,
so they are pre-fix rows rather than evidence.

**F2 — No real Read or Do exists anywhere.** Every one of the 8 `checks` rows is seeded
fixture text (four independent proofs in the provenance section above), and
`source = 'generated'` appears zero times in the table. The app's single most prominent
output has no verified live sample, so the G1/G2/G4 guardrails on generated card copy are
untested against real output.

**F3 — One Talk call was claimed, no reply survived.** `ai_usage.by_type.sage = 1` for
`test` on Aug 29, but `sage_messages` has 0 rows and `dev_trace_events` has 0 rows. Whatever
came back was never persisted or traced. Matches the open "Live Talk failure".

**F4 — Trace has never captured anything.** `dev_trace_events` is empty even though a live
Explore pack and a live question batch were generated on Aug 29. The pipeline viewer shipped
to production OTA with no capture on record.

**F5 — Explore body content does not clearly match its tagged axis.** Entry 0 is tagged
`traits: ["openness"]` but the prose is about short sleep and alone-time reset
(`knocks_you_off` + `recovery_style`). Entry 1 is tagged `extraversion` but is about alone
time and `current_focus`. G3 ("one trait at a time") is satisfied numerically — one axis per
entry — but the stored axis tag is not what the text is actually reflecting, which makes the
"did this land?" feedback loop harder to trust.

**F6 — A live Explore pack was generated without an `explore` quota claim.** `explore_packs`
has one row for `test` on `2026-08-29` with two live-model entries, but that day's
`ai_usage` row shows `calls: 1` and `by_type: {"sage":1,"questions":1}` — no `explore` key.
`routeExplore` only claims when both `claimAiCall` and `generateBody` deps are wired
(`src/lib/explore/route.ts:99`). Separately, `docs/stage8-audit.md` already records that
Read/Do generation never calls `claimAiCall` at all.

**F7 — `is_founder` disagrees with the docs.** `docs/ME.md` states "`is_founder` is a
root-flipped ME flag (emci is on)", but all 6 rows in the live `me` table, including
`handle = 'emci'`, have `is_founder = false`. Cosmetic only, so nothing is broken — but the
Founder badge is not actually showing for anyone.

## Orphaned outputs — built or shipped, no current render location

**O1 — Stored facts (`me.facts`).** Users can teach Sage a fact from `src/app/chat.tsx`, and
that fact drives the depth growth tier, the `first-fact` badge, the Nudge fact branch, the
Reveal fact branch, and prompt grounding. **No screen anywhere lists a user's stored facts,
and none lets them edit or delete one.** It is the only user-authored free text in the
product and it is invisible after the moment of writing.

**O2 — Explore reactions (`explore_reactions`).** The "Did this land?" tap has a write path
and a consumer (`loadMissNotes` feeds the next prompt), but no surface ever shows the user
that their feedback changed anything, and the table has 0 rows.

**O3 — `talk_style` has no visible effect surface.** It is editable as one of the 9 chips and
it seeds Sage's tone in the prompt builder, but nothing on any screen reflects the tone
setting back, and it is explicitly barred from the Nudge signal set. A user changing it gets
no confirmation that anything moved.

**O4 — Four of five `voice_preset` values are unreachable in practice.** The picker on You
offers 5 presets; all 6 accounts are on the `close_friend` default and no other preset has
ever been stored.

**O5 — Bank content stops at day 3, with no day-4+ fallback.** `first_cards.md` holds days
1–3 only, and `bankCardForMe` returns `null` beyond that. A consent-denied or consent-pending
account past day 3 therefore has **no card path at all** — not bank, not model. `emci`,
`yeezy`, and `zintake9` all have `ai_consent = null`, so they are already on that path.

**O6 — Trait axis numbers, sources, and timestamps have no user-facing surface beyond a
band.** `trait_sources`, `trait_touched_at`, and `sage_knows` are never rendered — by design
— but combined with O1 it means nothing on any screen shows a user *why* Sage thinks what it
thinks. The bands show position without provenance.

**O7 — `sage_messages` persistence is wired but empty.** Sage replies are persisted
specifically so they can be reported (`src/app/(tabs)/sage.tsx:54`), which means the report
path for a Sage reply has never been exercised on real data.
